# 山间有茗 · 茶叶产品展示网站

纯 HTML + CSS + 原生 JavaScript，无安装、无构建、无 CDN、无后端或数据库。全部运行资源已保存在本目录。

## 本地使用

1. 用现代浏览器打开 `index.html`，即可浏览 4 款示例茶。
2. 点击“设置”，输入管理密钥 **888888**。登录有效期为 2 小时，可主动退出。
3. 填写名称、产地、年份、种类、简介和图片，点击保存。种类可选择已有项或直接输入新分类。
4. 在右侧列表编辑、删除；前台列表、分类、详情及同一来源的其他标签页自动同步。

图片支持 JPG、PNG、WebP，原图上限 8 MB。上传后自动压缩为最长边 1200px 的 JPEG，并以 Base64 写入 localStorage；透明区域会铺上米白色。示例图片随站点保存在 `assets/`，不消耗 Base64 图片存储空间。

若浏览器限制 `file://` 下的 localStorage，请通过静态预览或 GitHub Pages 使用。网站不依赖 Node.js；可选的开发检查文件也不影响直接运行。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `index.html` | 首页、详情、后台与登录弹窗 |
| `styles.css` | 国风配色、响应式布局与交互样式 |
| `app.js` | 动态分类、搜索、路由、管理、图片压缩及本地保存 |
| `data/products.js` | 首次访问载入的公开茶叶数据 |
| `assets/` | 本地茶席、茶叶图片、图标与图片生成说明 |
| `.nojekyll` | 告诉 GitHub Pages 直接提供静态资源 |
| `verification/` | 开发验收记录、截图及可选检查脚本，无需上传 |

## GitHub Pages 部署

1. 在 GitHub 新建仓库，例如 `tea-collection`。
2. 将 `index.html`、`styles.css`、`app.js`、`data/`、`assets/` 和 `.nojekyll` 上传至仓库根目录并提交到 `main`；保留文件夹结构。
3. 打开仓库 **Settings → Pages**。
4. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
5. 选择 **main** 分支与 **/(root)**，点击 **Save**。
6. 等待 Pages 部署完成，访问设置页提供的网址，通常为 `https://用户名.github.io/tea-collection/`。

也可将完整站点放在仓库 `docs/` 目录，发布源选择 `/docs`。若放在其他子目录，保持结构完整，并从已发布站点对应的子目录 URL 访问。资源均使用相对路径；详情采用 `#tea/产品ID` 路由，直接刷新详情不会触发服务器 404。

步骤依据：[GitHub 官方 Pages 发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。本次交付未连接 GitHub 或进行公开发布。

## 本地数据与公开更新

**localStorage 只属于当前浏览器和当前网站来源。** 修改保存在本机，不会自动传到 GitHub，也不会让另一台设备上的访客同步修改。不同浏览器、无痕窗口、本地文件与线上网址的数据彼此独立；同一来源的其他标签页可实时同步。清理浏览器站点数据会删除本地修改。

要把后台整理后的茶叶公开给访客：

1. 在后台点击“导出公开数据”，下载 `products.js`，同时保留一份备份。
2. 用下载文件替换仓库内的 `data/products.js` 并提交；新增上传图片已包含在该文件的 Base64 数据中。
3. 等待 GitHub Pages 重新部署。初次访问的浏览器会载入这份新数据。
4. 已有本地数据的浏览器优先保留原数据。如需载入新公开版本，请先导出备份，再清除此站点的浏览器存储并重新打开。单纯刷新不会覆盖本地数据。

备份恢复：将备份的 `products.js` 放回 `data/` 目录，然后在已备份的前提下清除该站点旧存储并重新打开。示例图片路径依赖 `assets/`，备份完整站点时应同时保留该目录。

浏览器容量取决于环境，Base64 比图片原文件更大。后台显示数据体积估算；达到配额时会明确提示并保留原数据，表单内容不会因写入失败而清空。不可将浏览器存储当作唯一备份。

固定密钥 **888888** 是按需求实现的简易管理入口，可以从前端源码查看或绕过，不属于安全的服务器身份验证。该方案适合本地编辑和静态展示，不提供跨设备后台、真实账户权限或云端数据同步。

## 手动修改

- 站点名与首页文字：编辑 `index.html`。
- 配色：编辑 `styles.css` 开头的 `:root` 变量。
- 登录密钥、有效期、上传上限：编辑 `app.js` 开头常量。
- 示例茶叶：编辑 `data/products.js`；每条 `id` 保持唯一，`image` 使用 `./assets/文件名.jpg` 或合法图片 Base64。
- 4 款产品的产地、年份、风味及 AI 图片都是展示示例，上线前可替换为实际产品资料。

本次实测环境为本机 Chromium 浏览器及桌面、手机尺寸预览。详细验收情况见 `verification/验收记录.md`；未实际逐一运行 Safari、Firefox 或真实手机设备。
